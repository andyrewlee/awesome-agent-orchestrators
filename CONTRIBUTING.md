## Contributing

Suggestions are appreciated. Keep them focused on tools for orchestrating autonomous agents — parallel coding agents, swarms, loop runners, task runners, personal assistants, and the infrastructure beneath them.

### Acceptance criteria

- **Open** — the project is open source or source-available, with a pointable GitHub repository. Entries link to the repo, not a marketing site.
- **Adopted** — at least 5 GitHub stars and signs of life (recent commits or releases). Strong projects early in their life are welcome back once they have traction.
- **Fitting** — the project clearly belongs to one existing section without diluting it. Projects that span several are placed where their center of gravity is.
- **Described** — one line in the established style: start capitalized, end with a period, say what it does and which agents it supports.

### Mechanics

- Entries are sorted alphabetically within each section, case-insensitive.
- Projects that go quiet move to **Resting** with a `_(last commit YYYY-M)_` note rather than being deleted, and return if development resumes.
- One entry per PR keeps review quick. Title it `Add X to <Section>` and keep the body to one line.

The README is linted with [awesome-lint](https://github.com/sindresorhus/awesome-lint) in CI and must pass it.
